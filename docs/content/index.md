# HikariPb

HikariPb is a lightweight implementation of Protocol Buffers (proto3) that generates encoders, decoders and protocol
documentation from the `.proto` files of a protocol. The generation is performed by `protoc-gen-hikaripb`, a `protoc`
plugin that is invoked through the `--hikaripb_out` option and provides four generators.

## Generators

The generator is selected with `type=` in the `--hikaripb_out` parameter. The generators are independent of each
other: to produce several outputs from the same `.proto` files, run `protoc` once per generator.

| `type=` | Output | Provided by the user |
|---------|--------|----------------------|
| `c` | A C encoder/decoder runtime and one `.pb.h`/`.pb.c` pair per `.proto` file. | A `<prefix>_config.h` (field sizes, print macros) and the read and write functions of the transport. |
| `cpp` | A native C++17 codec: the `Encoder` and `Decoder` templates and one `.pb.h` per `.proto` file. | A `<prefix>_config.h` with the field sizes and two stream classes. |
| `py` | One `_pb.py` module per `.proto` file, based on a pure Python runtime module that can optionally be compiled with Cython. | Nothing; the Python standard library is sufficient. |
| `sphinxdocs` | The documentation of the protocol as [Sphinx](https://www.sphinx-doc.org) pages in MyST Markdown, generated from the comments of the `.proto` files. | Optionally an existing Sphinx project; by default, the output is a standalone project. |

The comments of the `.proto` files are carried over into every output: they become the comments of the C and C++
headers, the docstrings of the Python classes and the text of the documentation.

## Requirements

- `protoc` on the `PATH`, with support for `--experimental_allow_proto3_optional`.
- Python 3.10 or later with the packages listed in `protoc/requirements.txt` (`protobuf`, `jinja2`) to run the plugin.
- Optional: `clang-format` 11 or later on the `PATH` to format the generated C and C++ code. Without it, the code is
  generated unformatted.
- To build the generated code: a C11 compiler for `c` and a C++17 compiler for `cpp`. `py` requires only Python;
  Cython, setuptools and a C compiler are optional and accelerate the codec. `sphinxdocs` requires `sphinx` and
  `myst-parser` to build the pages (`pip install sphinx myst-parser`).

## Quick start

The following commands generate the Python bindings of the weather example in the repository:

```sh
pip install -r protoc/requirements.txt
mkdir -p out
protoc --experimental_allow_proto3_optional \
    --plugin=protoc-gen-hikaripb=protoc/hikaripb.py \
    --proto_path=examples/proto \
    --hikaripb_out=type=py,prefix=weather_py:out \
    examples/proto/weather.proto
```

The directory `out/` then contains `weather_pb.py` and `weather_py_codec.py`. To use another generator, replace
`type=py` with `type=c`, `type=cpp` or `type=sphinxdocs`; the overview page of each generator describes how to use its
output.

- On native Windows, `protoc` cannot start a Python script as a plugin. Use `protoc\protoc-gen-hikaripb.bat` as the
  plugin (`--plugin=protoc-gen-hikaripb=protoc\protoc-gen-hikaripb.bat`; the environment variable `PYTHON` selects
  the interpreter) together with an absolute `--proto_path`.
- `hikaripb.py --help` lists every option with its default value.

## Contents

- [Generator options](options.md): the syntax of the `--hikaripb_out` options, the configuration file and the options
  shared by all generators (`prefix`, `single_file`, `ignore`, `namespace_override`).
- [Encoding and decoding](how-it-works.md): on-the-fly encoding, the operation of the decoder, and the resulting
  requirements for the transport and the memory.

Each generator has a section with two pages: an overview, which describes how to generate and use the output, and the
configuration options, which list the `--hikaripb_out` options that the generator reads and the settings of the
generated library. The sections of the C and C++ generators also describe field callbacks, which pass a field to an
application function during decoding: [C](c/callbacks.md), [C++](cpp/callbacks.md).
